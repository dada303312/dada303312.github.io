## 二、当前最直观的成果

游戏已经开始形成“幸存者 Like”的标准闭环：

1. 玩家四方向移动，镜头平滑跟随。
2. 玩家周期性寻找最近的敌人并自动发射子弹。
3. 敌人持续追赶玩家，被击中后闪白、掉血、击退并显示伤害数字。
4. 敌人死亡后掉落经验宝石。
5. 宝石被玩家拾取后增加经验。
6. 经验达到门槛时暂停游戏，弹出三个升级方向。
7. 选择后恢复游戏，继续战斗。

## 三、模块拆解

### 1. 工程基础

`project.godot` 已完成基础配置：

- 主场景指向 `main.tscn`。
- 逻辑分辨率为 `640 × 360`，适合后续制作像素风。
- 使用 `viewport` 拉伸，低分辨率画面可以放大到窗口。
- 默认纹理过滤关闭，像素素材放大时不会自动变糊。
- Windows 渲染驱动设置为 D3D12。
- 物理引擎设置为 Jolt Physics。

这说明工程已经为“低分辨率像素风”提前留好了基础设置。

### 2. 玩家移动与自动射击

`player.gd` 已经承担了玩家本体、经验、等级和自动攻击四类职责。

当前参数：

| 属性 | 数值 |
|---|---:|
| 移动速度 | 180 px/s |
| 自动攻击间隔 | 0.4 s |
| 基础伤害 | 10 |
| 子弹击退 | 160 |
| 初始升级门槛 | 10 XP |
| 后续升级门槛 | 每级 ×1.3 |

自动瞄准的实现方式是遍历 `enemy` 组，比较与玩家的距离平方，选择最近的敌人。当前是单体直线子弹流派。

### 3. 敌人生成与追击

`main.gd` 监听 `SpawnTimer`，每 0.6 秒生成一个敌人。生成位置为玩家周围 380～450 像素的圆环，也就是固定在屏幕视野之外。

`enemy.gd` 中的主要参数：

| 属性 | 数值 |
|---|---:|
| 追击速度 | 80 px/s |
| 最大生命 | 20 |
| 击退摩擦 | 600 |
| 掉落 | 1 颗经验宝石 |

敌人受伤时会闪白，同时生成一个向上漂移并淡出的伤害数字。

### 4. 子弹命中与反馈

`bullet.gd` 使用 Area2D 的 `body_entered` 检测敌人。命中后：

- 对敌人调用 `take_damage(damage, direction * knockback_force)`。
- 子弹立即销毁。
- 如果没有命中，3 秒后自动销毁，避免无限堆积。

### 5. 经验与升级界面

经验宝石是 Area2D，进入玩家 `PickupArea` 后立即：

- 给玩家增加 1 XP。
- 销毁宝石节点。
- 达到门槛后暂停当前场景树。
- 实例化 `level_up_ui.tscn`。

升级界面包含三个按钮：

| 选项 | 当前效果 |
|---|---|
| 加速度 | 移动速度 ×1.10 |
| 加伤害 | 当前伤害 ×1.15 |
| 加攻速 | 攻击间隔 ×0.90 |

UI 的 `process_mode` 设置为 Always，因此主场景暂停后按钮仍可点击。

## 四、工程文件结构

```text
项目根目录
├─ project.godot
├─ main.tscn / main.gd
├─ player.tscn / player.gd
├─ enemy.tscn / enemy.gd
├─ bullet.tscn / bullet.gd
├─ exp_gem.tscn / exp_gem.gd
├─ level_up_ui.tscn / level_up_ui.gd
└─ icon.svg
```

当前结构适合做机制原型，但还属于“扁平目录”。随着敌人类型、升级池、武器、波次和美术资源增多，下一步需要把脚本、场景和资源分组管理。

## 五、运行验证

为了不影响原工程，我在独立运行副本中完成了两次验证：

- 主场景成功运行，敌人、子弹、玩家和伤害文字正常渲染。
- 升级 UI 场景成功单独运行，三个升级按钮正常显示。
- 自动截图成功生成战斗画面和升级界面。

本次运行日志没有发现 GDScript 语法错误或运行时脚本中断。副本因没有携带原工程 `.godot` 缓存，出现了 UID 回退到文本路径的警告；这是复制方式导致的缓存现象，不等同于原工程逻辑错误。

## 七、观察到的技术点

这些不是马上要改的清单，只是当前代码里值得记录的工程事实：

- `player.gd` 同时管理移动、攻击、经验、等级和 UI，职责已经开始集中。
- 升级选项直接写死为三种数值修改，还没有独立的数据层。
- 经验达到门槛后直接清零，如果一次获得超过一级所需经验，多余经验会丢失。
- 宝石当前是“接触即拾取”，代码注释中的“飞入吸附”还没有实现。
- 敌人只有一种，生命周期、掉落、追击和伤害反馈都集中在一个脚本里。
- 波次只使用固定 0.6 秒间隔，没有随时间变化的难度曲线。
- UI 没有防止重复弹窗的保护，也没有选择历史或构筑展示。
- 当前所有视觉节点都是 ColorRect，适合先验证机制，但还不能体现目标中的像素风品质。

## 八、阶段结论

![阶段评估](/images/blog/godot-survivors-progress/05-progress.svg)

这个工程已经越过了“只有一个角色会动”的阶段。玩家、敌人、子弹、掉落、经验、等级和升级选择都已经是可运行代码，并且能够形成一次最基本的战斗循环。

它现在的准确定位是：

> **一个已经验证核心机制的幸存者 Like 原型，而不是一个已经完成的游戏。**
